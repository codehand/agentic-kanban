Workflow no-self-certification lifecycle, gate-enforced

Every task on this board moves through a fixed state machine driven by four separate actors: an implementer writes the code, a machine gate grades fresh evidence (exit codes, checksummed), an independent judge reviews the diff, and a human gives the only approval that can mark a task DONE. No agent ever certifies its own work — that is the point of the design.

State machine

The stages in detail

TODO acts next: implementer

The task spec lives in .ai/tasks/<ID>/ with acceptance criteria, ideally machine-verifiable as an .ac.sh script. When the implementer claims it (TODO → IN_PROGRESS), the gate creates the task branch plus an isolated git worktree per repo and records the base commit (base_sha).

IN_PROGRESS actor: implementer

The implementer writes code and real tests only inside the worktree, commits them onto the task branch, and writes a narrative report (reports/<ID>/implementer.md). The implementer may run build/test locally for confidence, but nothing it claims counts as evidence.

IMPLEMENTED gate guard on entry

The gate accepts IN_PROGRESS → IMPLEMENTED only if the implementer report exists, every repo’s main checkout is clean with HEAD == base_sha (no code leaked outside the worktree — a leak is an instant reject), and the worktree has real changes vs base (no-op claims are rejected).

SELF_CHECK_PASSED decided by: gate, from runner evidence

A runner script (run-evidence.sh) freshly regenerates the evidence in the worktree: build and test logs with their exit codes (build.exit, test.exit), the acceptance-criteria script result (ac.exit), and a manifest.json with a sha256 per file. The gate sets this state only when build.exit == 0 && test.exit == 0 && ac.exit == 0 and every checksum matches. Lint and coverage are checked per config (warn when optional, block when required).

SELF_CHECK_FAILED decided by: gate · rework

Any non-zero exit code lands here. The only way out is the dashed rework edge: the implementer takes the task back to IN_PROGRESS, fixes the code in the same worktree, and the evidence is regenerated from scratch. Stale or hand-edited evidence never passes — the checksums would not match.

JUDGE_PASSED actor: judge

An independent judge (its own role and token, ideally a different model/session than the implementer) reviews the diff against base plus the evidence, and writes reports/<ID>/judge.md. The gate requires the literal line VERDICT: PASS; the judge may not contradict the recorded exit codes. The task now waits for a human.

JUDGE_REJECTED actor: judge · rework

The judge rejects with written reasons (semantic problems, weakened tests, unmet acceptance criteria). Like a failed self-check, the task goes back to IN_PROGRESS for the implementer to address the feedback.

DONE actor: human — only

Human approval is the single way to finish a task. The gate refuses JUDGE_PASSED → DONE from any actor other than human, and there is no fast path that skips the judge. Approval does not auto-merge the branch; merging stays an explicit human git action.

Why no-self-certification

An agent saying “tests passed” proves nothing — agents are rewarded for finishing and will happily grade their own homework. This workflow removes that option:

  • Evidence is machine-recorded. Exit codes are written by the runner script, not by prose; files are checksummed in manifest.json and made read-only, so tampering breaks the hash.
  • Evidence must be fresh. It is regenerated for the current code on every check — reusing an old green run does not work.
  • The gate is a script, not an agent. It rejects every transition outside the table above and never accepts a self-check without all exits at zero.
  • The judge is decorrelated. A separate role and token (run it on a different model for real independence) reviews semantics the exit codes cannot see.
  • A human holds the only terminal authority. DONE requires the human role — the gate blocks everyone else.

Roles & permissions

Role to permission mapping: which state transitions and other actions each role may perform.
Role State transitions allowed Other permissions
human JUDGE_PASSED → DONE (approve)
rework: SELF_CHECK_FAILED / JUDGE_REJECTED → IN_PROGRESS		 create / update / reset / remove task · mint / revoke token · review comment · read
implementer TODO → IN_PROGRESS
IN_PROGRESS → IMPLEMENTED
rework: SELF_CHECK_FAILED / JUDGE_REJECTED → IN_PROGRESS		 claim task · update task · narrative comment · set gitref · read
self-check IMPLEMENTED → SELF_CHECK_PASSED / SELF_CHECK_FAILED narrative comment · read — no code changes
judge SELF_CHECK_PASSED → JUDGE_PASSED / JUDGE_REJECTED verdict comment · read
runner none submit evidence only · read — no transitions, no comments

This matrix is enforced server-side (server/src/auth/authorize.ts): a request authenticated with a role that is not permitted to perform an action gets 403, no matter what the UI shows. Keeping the runner credential separate from the implementer is the core anti-self-certify guard.
