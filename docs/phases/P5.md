# P5 — MCP server (tool surface, Streamable HTTP)

> Nguồn: `IMPLEMENTATION_PLAN.md` §5 (P5), §3 (SDK + Streamable HTTP) · `TASK_HUB_DESIGN.md` §6 (MCP
> tools), §2 (transport Streamable HTTP).

## Mục tiêu

Agent kết nối qua **MCP (Streamable HTTP)** và thao tác đủ vòng đời task. Mỗi tool ghi đi qua
auth(role) + gate/service — handler không tự ghi state.

## Phạm vi

In scope:
- Mount `@modelcontextprotocol/sdk` server + **Streamable HTTP** vào process (`node:http`), kèm bearer.
- Đăng ký tools `TASK_HUB_DESIGN.md` §6 với **zod** schema:
  - *Đọc:* `project.list/create`, `task.list/get/next`, `comment.list`, `evidence.get`, `gitref.list`.
  - *Ghi:* `task.create/claim/heartbeat/release/transition`, `gitref.set`, `comment.add`,
    `evidence.submit`, `task.selfcheck`, `task.approve`.
- Mỗi tool: validate input (zod) → auth(role) → gọi service (gate P3 / evidence P4 / repo P1) → map
  lỗi domain → MCP error.

Out of scope: lease semantics đầy đủ (P6 chi tiết claim/heartbeat/expiry); JSON read API + UI (P7).

## Module & file

- `server/src/mcp/server.ts` — tạo SDK server + mount Streamable HTTP route `/mcp`.
- `server/src/mcp/tools/*.ts` — đăng ký từng tool + zod schema.
- `server/src/mcp/errors.ts` — map lỗi domain → MCP error.

## Acceptance criteria

- MCP client (SDK) kết nối Streamable HTTP kèm bearer — integration test.
- Happy path đầy đủ `TODO→IN_PROGRESS→IMPLEMENTED→SELF_CHECK_PASSED→JUDGE_PASSED` qua tools, mỗi role
  dùng token riêng — integration test.
- `implementer` token gọi `evidence.submit` → tool trả lỗi role — integration test.
