# P1 — Data layer (SQLite schema + repositories)

> Nguồn: `IMPLEMENTATION_PLAN.md` §5 (P1) · `TASK_HUB_DESIGN.md` §4 (data model).

## Mục tiêu

Persistence trung thực với data model trong `TASK_HUB_DESIGN.md` §4: 7 bảng, append-only cho
`evidence`/`transition`, repository functions typed. Đây là nền dữ liệu cho gate (P3) và evidence (P4).

## Phạm vi

In scope:
- Migration SQL đánh số + runner nhỏ (idempotent) tạo **7 bảng**: `project, task, transition, comment,
  evidence, gitref, token` đúng cột trong `TASK_HUB_DESIGN.md` §4.
- Repository functions typed cho từng bảng (insert/select; `gitref` cho update `head_sha`/`mr_url`).
- **Append-only** cho `evidence` và `transition`: chặn UPDATE/DELETE bằng **SQLite trigger** + guard ở repo layer (defense-in-depth, `IMPLEMENTATION_PLAN.md` §7).
- Index theo `task.project_id`, `task.state`.

Out of scope: business rule transition (P3), auth resolve (P2), checksum verify (P4).

## Module & file

- `server/src/db/connection.ts` — mở `better-sqlite3`, pragma.
- `server/src/db/migrations/0001_init.sql` — 7 bảng + trigger append-only + index.
- `server/src/db/migrate.ts` — runner idempotent.
- `server/src/db/repositories/{project,task,transition,comment,evidence,gitref,token}.ts`.

## Task checklist

- [ ] Viết migration `0001_init.sql` đủ 7 bảng theo §4 design (cột, kiểu, NULL).
- [ ] Trigger chặn UPDATE/DELETE trên `evidence` và `transition`.
- [ ] Index `task(project_id)`, `task(state)`.
- [ ] Runner migrate idempotent (chạy lại không lỗi).
- [ ] Repository functions typed + guard append-only ở repo layer.
- [ ] Unit test: CRUD cơ bản + reject UPDATE/DELETE append-only.

## Acceptance criteria

- Migration tạo đủ 7 bảng; chạy lại không lỗi (idempotent) — test.
- CRUD cơ bản từng bảng — unit test pass.
- UPDATE/DELETE một dòng `evidence` hoặc `transition` → **bị từ chối** — test.

## Ánh xạ design

- Bảng & cột: `TASK_HUB_DESIGN.md` §4 (`project/task/transition/comment/evidence/gitref/token`).
- Append-only `evidence`/`transition`, `gitref` cập nhật được: `TASK_HUB_DESIGN.md` §4 (cuối) + §7.3.
- Defense-in-depth (trigger + checksum): `IMPLEMENTATION_PLAN.md` §7.
