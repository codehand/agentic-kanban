# P8 — Tích hợp engine `.ai/` (thin client)

> Nguồn: `IMPLEMENTATION_PLAN.md` §5 (P8), §1 (standalone trước) · `TASK_HUB_DESIGN.md` §12 (tích hợp
> `.ai/`), §10 (git/MR multi-repo).

## Mục tiêu

CLI quen thuộc (`gate.sh` / `run-evidence.sh` / `new-task.sh`) chạy **trên server**: trở thành thin
client gọi MCP tool, đúng `TASK_HUB_DESIGN.md` §12. Chỉ làm **sau khi** server standalone (P0–P7) xong.

## Phạm vi

In scope:
- `gate.sh` `propose/selfcheck/approve` → gọi MCP tool tương ứng (`task.transition`, `task.selfcheck`,
  `task.approve`); giữ CLI cho người quen dùng.
- `run-evidence.sh`: vẫn build/test **local trong worktree** nhưng `evidence.submit` lên server bằng
  token **runner** (thay vì ghi `.ai/evidence/*` local).
- `new-task.sh` / `/newtask` → `task.create` trên server.
- Ánh xạ worktree/gitref local ↔ `gitref.set` (branch/base/head/MR URL) trên server.
- Giữ fallback file cho offline (tuỳ chọn).

Out of scope: thay đổi state machine; tự gọi git host API / auto-merge (`IMPLEMENTATION_PLAN.md` §10).

## Module & file

- `.ai/scripts/gate.sh` — propose/selfcheck/approve gọi MCP.
- `.ai/scripts/run-evidence.sh` — build/test local + `evidence.submit` (runner token).
- `.ai/scripts/new-task.sh` — `task.create`.
- client nhỏ gọi MCP/HTTP (bearer theo role).

## Task checklist

- [ ] `gate.sh propose` → `task.transition` trên server.
- [ ] `gate.sh selfcheck` → `task.selfcheck`; `approve` → `task.approve`.
- [ ] `run-evidence.sh` build/test local rồi `evidence.submit` (runner).
- [ ] `new-task.sh` → `task.create`.
- [ ] Ánh xạ gitref local → `gitref.set` (đơn-repo & đa-repo).
- [ ] Integration: transition đẩy lên server; evidence ghi nhận; flow đa-repo chạy.

## Acceptance criteria

- `gate.sh propose` đẩy 1 transition trên server — integration.
- `run-evidence.sh` submit evidence (runner) và server ghi nhận — integration.
- Flow worktree đơn-repo & đa-repo vẫn chạy với server.

## Ánh xạ design

- `gate.sh` / `run-evidence.sh` / `new-task.sh` thành thin client: `TASK_HUB_DESIGN.md` §12.
- Evidence runner-only khi submit lên server: `TASK_HUB_DESIGN.md` §7, §12.
- gitref multi-repo (branch/base/head/MR): `TASK_HUB_DESIGN.md` §10 + §4 (`gitref`).
- Standalone trước, integration sau: `IMPLEMENTATION_PLAN.md` §1, §4.1.

## Phụ thuộc & rủi ro

- **Phụ thuộc:** P5 (MCP tools), P6 (lease). Sau toàn bộ standalone.
- **Rủi ro:** ánh xạ worktree/gitref local ↔ `gitref.set` server; "main sạch + code worktree" không
  cưỡng chế từ xa → hạ xuống "branch push remote, head>base" (`TASK_HUB_DESIGN.md` §1.5, §13;
  `IMPLEMENTATION_PLAN.md` §9).
