# P2 — Auth & roles (token theo role)

> Nguồn: `IMPLEMENTATION_PLAN.md` §5 (P2) · `TASK_HUB_DESIGN.md` §3 (auth & roles), §1.3 (role = quyền tách biệt).

## Mục tiêu

Lớp chống self-certify **trung tâm**: quyền = role của token, cưỡng chế phía server. Mọi tool-call mà
role không có quyền bị từ chối. Token lưu **chỉ hash**, secret trả về một lần khi mint.

## Phạm vi

In scope:
- Bearer parse middleware (trên `node:http`), resolve `{role, project_scope, token_id}` từ secret_hash.
- Bootstrap `ADMIN_TOKEN` (env/config) → tạo đúng 1 token `human` (idempotent).
- `token.mint(role, project?)` → trả secret **một lần**, lưu **SHA-256 + salt**; `token.revoke`.
- Helper `authorize(role, action)` map role→quyền theo bảng `TASK_HUB_DESIGN.md` §3.
- So sánh hash constant-time; **không log secret** (`IMPLEMENTATION_PLAN.md` §7 security).

5 role theo §3: `human`, `implementer`, `self-check`, `judge`, `runner`.

Out of scope: dùng `authorize` trong gate transitions (P3), trong MCP tools (P5), trong API (P7).

## Module & file

- `server/src/auth/parse.ts` — bearer parse middleware.
- `server/src/auth/resolve.ts` — secret → token row (hash compare constant-time).
- `server/src/auth/authorize.ts` — bảng role→action.
- `server/src/auth/bootstrap.ts` — `ADMIN_TOKEN` → human (idempotent).
- `server/src/auth/mint.ts` — mint/revoke; hashing util.
