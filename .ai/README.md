# AI Development Workflow — Quickstart

No AI agent may self-certify completion. Work flows:

```
TODO → IN_PROGRESS → IMPLEMENTED → SELF_CHECK_PASSED → JUDGE_PASSED → DONE
```

Full design & rationale: **`.ai/WORKFLOW_DESIGN.md`**.

## The one rule
Agents *propose*; the deterministic gate (`.ai/scripts/gate.sh`) *decides*. Evidence is produced only by `.ai/scripts/run-evidence.sh` (locked, checksummed). Agents cannot write `.ai/evidence/` or `.ai/state/` — a PreToolUse hook blocks them.

## Worktree isolation & multi-repo (1 task = N repos)
Every task is isolated on its own branch + git **worktree** — one per repo it touches. The task md declares:
- `Repos: <r1> <r2> …` — repos (paths relative to the engine root) the task changes. Default `.` (single repo). A multi-repo workspace (folder of independent git repos) lists several.
- `Branch: fix/<TASK>-<slug>` — one branch name shared across every repo (slug AI-generated from the title).

Entering `IN_PROGRESS` makes the gate create branch + worktree per repo at `<repo>/.claude/worktree/<branch>` (branched from each repo's **current** branch HEAD; base recorded in state). The Implementer works **only inside the worktrees** — if task code leaks into any repo's main checkout, the gate **REJECTS** the move to IMPLEMENTED. Build/test/coverage and the Judge's diff all run inside the worktrees. `approve` does **not** auto-merge — you open the MR/merge each repo's branch yourself, or run `/merge <TASK>` after DONE for a conflict-safe local merge. `gate.sh worktrees <TASK>` prints the paths.

## Deploy to another project (portable)

The whole engine lives in `.ai/`. To reuse it in another repo:

**Prerequisites in the target repo:** it's a git repo, `jq` is installed, and you know its build/test commands (this engine is adapted for **Node/pnpm + vitest** by default; e.g. `pnpm test`, or swap for `go test ./...`, `pytest`).

```bash
# 1. Copy the engine (NOT the instance data — state/evidence/reports are per-project).
#    From the source project root:
rsync -a --exclude tasks --exclude state --exclude evidence --exclude reports \
      .ai/  /path/to/target-repo/.ai/
#    (or: cp -r .ai /path/to/target-repo/ then delete tasks/ state/ evidence/ reports/)

# 2. Wire it into the target repo's Claude Code setup.
cd /path/to/target-repo
bash .ai/install.sh        # copies subagents+commands into .claude/, merges the hook,
                          # makes scripts executable, creates empty instance folders

# 3. Adapt config.yml to the target project's stack (see checklist below).
$EDITOR .ai/config.yml

# 4. Open a NEW Claude Code session so the PreToolUse hook loads. Done.
```

`install.sh` is **idempotent** — safe to re-run after you pull engine updates; it won't duplicate the hook and only overwrites the workflow's own files in `.claude/` (it leaves your other agents/commands/settings untouched).

### Per-project customization checklist
Most of the engine is project-agnostic. These are the only things you normally touch:

| File | What to change for a new project |
|------|----------------------------------|
| `.ai/config.yml` → `commands.build/test/lint` | The actual build/test/lint commands for that stack. **`run-evidence.sh` reads these.** Default `pnpm build` / `pnpm test` / `pnpm lint` (Node + vitest). |
| `.ai/config.yml` → `checks` | Flip `lint`/`coverage` to `required` if you want them to block; set the coverage `threshold`. |
| `.ai/scripts/run-evidence.sh` | **Only if not a Node/pnpm project.** It runs the `commands.*` above **per repo, inside each worktree**, and reads coverage from vitest's `coverage/coverage-summary.json`. A repo with **no `package.json`** yields `build/test = na` (not a fake `0`). Swap the coverage parsing for another stack if needed (keep the contract: loop `state.repos`, write aggregate `*.exit`, a checksummed `manifest.json`, and export `AI_WT_<REPO>` for `ac.sh`). |
| `.ai/tasks/<ID>/<ID>.ac.sh` | Per-task — written fresh for each task anyway. Anchor each repo via `${AI_WT_<REPO>:-$ROOT/<repo>}` so it runs against the worktree (the stub generated by `new-task.sh --ac` shows how). |

What you almost never change: `gate.sh`, `guard-protected-paths.sh`, the agent prompts, the slash commands, the state machine. They're stack-independent.

### Verify the install
```bash
.ai/scripts/gate.sh --help 2>/dev/null; echo "---"
# in a NEW session, the hook should block this:
#   try to Write a file under .ai/evidence/  → expect "BLOCKED"
ls .claude/agents .claude/commands           # implementer/self-check/judge + 6 commands present
jq '.hooks.PreToolUse[0].hooks[0].command' .claude/settings.json   # points to .ai/scripts/guard-protected-paths.sh
```

### Troubleshooting
- **Hook not blocking?** Claude Code loads `settings.json` only at session start — open a new session after install.
- **`jq: command not found` during install** — install jq (`brew install jq` / `apt install jq`).
- **Evidence step fails on a non-Go project** — you didn't adapt `run-evidence.sh` (step 3 / table above).
- **Want to update the engine across projects?** Edit the masters in `.ai/` (incl. `.ai/claude/`), copy `.ai/` over, re-run `install.sh`. Never edit `.claude/agents` or `.claude/commands` directly — they are install output and get overwritten.

## Create a task

From Claude Code (recommended — asks for Purpose/Scope/AC **and which repos**, fills the template + generates the branch slug):
```
/newtask Add request-ID middleware
```
Or deterministically from the shell (auto-picks the next `TASK-NNN`):
```bash
.ai/scripts/new-task.sh "Add request-ID middleware"                         # spec only, Repos=. Branch=fix/<ID>
.ai/scripts/new-task.sh "Cover timeout edge cases" --ac                      # also create an AC stub
.ai/scripts/new-task.sh "Wire FREE subscribe e2e" --ac \
      --repos "opf-auto-e2e api-marketplace" --branch "fix/<slug>"           # multi-repo
```
All register the task at `TODO` and create `.ai/tasks/<ID>/` with `Repos:`/`Branch:` lines. Then edit `.ai/tasks/<ID>/<ID>.md` (confirm `Repos:`/`Branch:`, fill requirements) and `<ID>/<ID>.ac.sh` if any.

## Run a task

Drive the stages from Claude Code:

```
/impl TASK-002        # Implementer subagent (sonnet) writes code → IMPLEMENTED
/selfcheck TASK-002   # Self-Check subagent runs evidence → gate sets SELF_CHECK_PASSED/FAILED
/judge TASK-002       # Judge subagent (opus, different model) → JUDGE_PASSED/REJECTED
/status TASK-002      # read-only status anytime
```

Finally, the **human** (only) approves:

```bash
.ai/scripts/gate.sh approve TASK-002       # JUDGE_PASSED → DONE (does NOT merge the branch)
```
`approve` only marks DONE — the task's branch + worktrees stay in place. Then push + open a PR with the merge helper (a human merges the PR on the git server):

```
/merge TASK-002       # (only after DONE) push each repo's worktree branch → origin,
                      # then open a PR into master. Worktree/branch are KEPT.
```

On conflict, `/merge` checks mergeability against `origin/master` with `git merge-tree` (no working tree touched). Mergeable → push the task branch + open the PR directly. Conflict → spin up an `integrate/<TASK>` worktree **off `origin/master`**, merge the task branch into it so conflicts land there, the agent resolves + commits, then `gate.sh merge-finish` pushes the integration branch and opens the PR (`integrate/<TASK>` → master). The human merges the PR on the server. PR creation uses the GitHub API (`gh` not required); the token comes from `GH_TOKEN`/`GITHUB_TOKEN` or the git credential helper.

## Models & running with independence (multi-terminal)

The subagents declare **no `model:`** — each inherits the model of the session that invokes it. So you choose the model *per role* by choosing which terminal you run the command in.

**Single terminal (simple):** run all four commands in one session. All roles share that session's model. You still get the strong guarantees (deterministic gate, isolated subagent context, adversarial judge prompt) — you just don't get *model* independence between Implementer and Judge.

**Two terminals (recommended for real independence — "paranoid mode"):**

| Terminal | Model | Run |
|----------|-------|-----|
| A — "work"   | e.g. Sonnet | `/impl <ID>` then `/selfcheck <ID>` |
| B — "review" | a **different** model, e.g. Opus | `/judge <ID>` |
| (either, human) | — | `.ai/scripts/gate.sh approve <ID>` |

Switch a terminal's model with `/model` (or launch with `--model`). Running `/judge` in terminal B means the judge subagent inherits Opus, decorrelating its blind spots from the Sonnet implementer — without hard-coding any model in the engine.

> Caveat: this relies on **you** running `/judge` in the different-model terminal. Nothing enforces it — if you run everything in one Sonnet session, the judge is also Sonnet. The deterministic gate still protects you regardless; model independence is the extra (human-maintained) layer.
>
> To pin a model without separate terminals instead, add `model: opus` back to `.ai/claude/agents/judge.md` and re-run `.ai/install.sh`.

## Operator commands
```bash
.ai/scripts/gate.sh worktrees TASK-002     # print branch + per-repo worktree paths
.ai/scripts/gate.sh merge  TASK-002        # (only after DONE) push worktree branch → origin + open PR into master per repo;
                                           # mergeable → push + PR directly; conflict → exit 2 (see /merge). Worktree/branch kept.
.ai/scripts/gate.sh merge-finish TASK-002  # after conflicts resolved+committed in the integration worktree: push it + open PR
.ai/scripts/gate.sh reset  TASK-002        # back to TODO; wipe evidence/reports + remove worktrees & branch
.ai/scripts/gate.sh remove TASK-002 --yes  # delete the task entirely (incl. worktrees & branch)
```

## Thin client — connect the workflow to a live Task Hub server

By default the workflow is fully local (state in `.ai/state/`). When the
environment variables below are set, `gate.sh` / `run-evidence.sh` / `new-task.sh`
**also** mirror every step to a running Task Hub server over MCP (so a shared
web UI sees task creation, transitions, gitrefs and evidence in real time). The
server keys tasks by `(project, key)` where `key` is the local `TASK-id`; server
pushes are best-effort (offline → a warning, local state still advances).

| Env var | Used by | Purpose |
|---------|---------|---------|
| `TASK_HUB_URL` | all `.ai/scripts/*` | Base URL of the Task Hub server (e.g. `http://127.0.0.1:3000`). Unset → local-only, no server calls. Also accepts `SERVER_URL`/`MCP_URL`/`BASE_URL`. |
| `TASK_HUB_TOKEN` | all | Bearer token for MCP calls (implementer role for `task.transition`/`gitref.set`). Also accepts `TASK_HUB_BEARER`. |
| `TASK_HUB_RUNNER_TOKEN` | `run-evidence.sh` | **Runner-role** token for `evidence.submit` — kept distinct from implementer credentials (evidence/agent separation). Falls back to `TASK_HUB_TOKEN`. |
| `TASK_HUB_SELFCHECK_TOKEN` | `gate.sh selfcheck` | **self-check-role** token for `task.selfcheck` (the server requires that role). Falls back to `TASK_HUB_TOKEN`. |
| `TASK_HUB_PROJECT` | all | Project slug on the server (default `default`). |

End-to-end proof that this wiring drives a real server through a full task
lifecycle (no mocks): `scripts/e2e-thin-client.sh` boots the real server, mints
the tokens above, and asserts the transitions / gitref / evidence landed on the
server. Run it after `pnpm build`.

## Layout

**Engine** (portable — copy to other projects):
- `install.sh`  wires `.claude/` (subagents + commands + hook) in the target repo
- `config.yml`  models per role + which checks are required/optional + thresholds + build/test commands
- `scripts/`    `gate.sh` (state+enforcement), `run-evidence.sh` (deterministic evidence), `new-task.sh`, `guard-protected-paths.sh` (hook)
- `agents/`     role contracts (docs)
- `claude/`     masters copied into `.claude/` by `install.sh` (`agents/`, `commands/`, `settings.hook.json`)

**Instance data** (per-project, generated, `.gitignore`d except tasks):
- `tasks/<ID>/`  one folder per task: `<ID>.md` spec (incl. `Repos:`/`Branch:`) + optional `<ID>.ac.sh` machine AC
- `state/`     `<TASK>.json` — state + `branch` + `repos{base_sha,base_ref,wt}` (gate-only) + `<TASK>.log` (audit)
- `evidence/`  machine-measured, locked 0444, checksummed: aggregate `*.exit`, `coverage.pct` (min), per-repo `coverage-<repo>.out`
- `reports/`   agent narratives: implementer.md / self-check.md / judge.md

Per-task git worktrees live at `<repo>/.claude/worktree/<branch>` (git-ignored), created/torn down by the gate — not part of `.ai/`.

## Tuning
Edit `.ai/config.yml`. `lint` and `coverage` are `optional` by default — flip to `required` to make the gate block on them. `build`/`test`/`ac` are always hard-required. `pipeline.fast_path` is locked `false`: every task goes through all four stages.
